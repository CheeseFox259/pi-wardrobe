# Keep complete distributions optional and review their agent files

The user requested complete Perfect Pi on 2026-10-15, superseding V1's simplified-reference scope while retaining the independent manager and isolated revision boundary. Native packages may declare a public wardrobe.agent footprint: explicit package files, confined agent-directory destinations, seed-only mutable defaults, and non-secret settings. The manager captures this footprint in the approval plan and materializes it only at explicit launch, supporting adapters that need agent-local scripts, roles, configuration and documentation without embedding Perfect Pi setup code in the manager or copying personal credentials and conversations. The original CPA reducer/compaction model policy remains unchanged and provider access is configured separately.


## Model ownership amendment — 2026-10-18

The user explicitly selected “models completely owned by Pi”, superseding the original CPA policy above and V1's model-preference fields. Wardrobe rejects `runtime.model` in presets and overlays, applies no model choice in soft use or branch restoration, and supplies no model defaults or provider configuration helper. Native Pi CLI arguments continue to reach Pi unchanged. Pi-owned model settings already saved in a revision are preserved, and model/auth files are excluded from the resource footprint and lock.

Perfect Pi no longer loads its compaction-model or subagent-policy adapters, pins no role or background-worker model, and seeds no reducer route. Native Pi owns ordinary compaction; the reducer follows the active Pi model, retaining request budgets and session/route-scoped consent. Upstream adapter sources remain available as historical source, not enabled resources. Revision isolation remains: Wardrobe does not copy or link global credentials into revisions. Existing model files are not deleted or migrated.


## Existing native Pi configuration amendment — 2026-10-18

The user subsequently requested direct use of the current native Pi models and configuration without another login. This supersedes the model/auth isolation clause above for the **Perfect Pi daily entry only**. Ordinary `wardrobe run` keeps its existing isolation contract.

A Pi 1.1.0 compatibility preload delegates model/auth creation and model settings operations to Pi's own stores at the original agent directory (`PI_CODING_AGENT_DIR` before launch, otherwise `~/.pi/agent`). Both probe and interactive child use this bridge. Pi retains its own locking, refresh and persistence; no auth/model files are copied, symlinked, seeded, reviewed or locked by Wardrobe. Native model defaults take precedence over old revision-local model settings. Resource packages, UI preferences, MCP and sessions remain revision-local. Native provider extensions are not implicitly loaded; custom providers configured in `models.json` work through Pi. Native model selection saved from Perfect Pi affects subsequent native Pi sessions by design.

The pinned ccstyle package now loads through a local cooperation adapter. It supplies write execution metadata inside the SoL-Pi file queue, preserving rich diffs and guarded action fusion without two competing registrations. Unknown third-party owners retain ccstyle's visible fallback. This adapter and the preload are compatibility code for the pinned Pi/package versions and must be checked when updating either pin.

## Footer-only TUI enhancement amendment — 2026-10-20

The user requested a replacement after the original configuration preset still emitted a ccstyle write-ownership warning. Real Pi reproduces the warning when that preset auto-discovers both the npm ccstyle entry and the local cooperation wrapper; the same duplicate reproduces without SoL. Selecting only one entry removes that warning. Installing a maintained derivative does not change an older session's binding to the original configuration preset.

Perfect Pi 1.0.3 supersedes the ccstyle cooperation decision above. Its selected TUI enhancement is `@narumitw/pi-statusline@0.50.2`, with Pi's built-in dark theme and native tool rendering. The footer displays model, context, tokens/cache and configured-price cost; the preset name remains a Wardrobe widget above the composer. SoL keeps its file queue, hash guard and guarded `then_run`, invoking native edit/write execution directly. No footer component owns write. The trade-off is losing ccstyle's custom write rich-diff renderer and other ccstyle-only presentation features; native edit diffs remain. Archived ccstyle source is retained outside auto-discovery directories, and old installed revisions and conversations remain recoverable.

`pi-statusline.json` is an explicitly reviewed mutable public configuration seed. This adds no model/provider setting or authentication ownership to Wardrobe. A TUI-only replacement is not evidence of an agent-quality or token-cost improvement; those claims require separately recorded real-model task comparisons.
