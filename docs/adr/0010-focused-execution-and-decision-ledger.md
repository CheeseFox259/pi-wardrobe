# Focused execution and a durable decision ledger

Status: implemented; native default-model acceptance pending.

ADR-0009 removed sequential batch gates, but its single combined review made final `verify` the apparent next action throughout an incomplete review and left progress, blocking and recovery at global scope. We retain autonomous ordering while adding model-selectable work-item focus, focused evidence, partial saves and a durable item ledger. Investigation activity, candidate/draft delivery and verification are different signals; bounded no-delivery recovery blocks only the current focus when independent work remains. Final coverage, candidate verification and installation sealing remain program-owned. Existing protocol-v3 drafts derive their item state without destructive migration.

This tradeoff keeps the complete change list available without requiring the model to manage a queue or inspect manager internals. It does not establish real-model completion or cost improvement; native default-model acceptance remains separate from deterministic and scripted-provider protocol evidence.

Paid trial 68 saved 26 decisions but retained program-generated no-delivery blockers for several of those same items. A delivery pause now records its program origin. A new submission covering that item's complete required decision set satisfies the pause, including when saved from another focus. Explicit model/user blockers remain unresolved until explicitly addressed; saved decisions and observations alone cannot clear those. This follows the meaning of the pause (missing delivery) without making the model separately acknowledge stale recovery bookkeeping. Coverage, behavior verification and READY_TO_INSTALL gates still apply.

Paid trial 65 also exposed a mismatch between saved decision labels and candidate work: the model integrated upstream changes into a local skill, then saved `adopt`; final verification copied the raw upstream text over its edits. Saving and verifying now reject adoption when it would discard a candidate edit, name the file and decision, and direct the model to `adapt`. Unmodified prepared local/upstream/clean-merge versions can still be intentionally adopted; local-overlap templates suggest adaptation. `adopt` continues to mean copying the original, while `adapt` preserves candidate edits. These checks prevent silent loss without making preset-specific product choices.

Paid trial 64 repeated the full frozen method and policy and the growing saved ledger on every routine call. Routine focus/save/verify/probe/checkpoint receipts now return skill references and a decision/count summary, with an explicit `details` call for recovery. Starting, resuming and requesting details still return the full frozen content; persisted/native details remain complete. Verification retains every diagnostic once and removes a repair copy only when all its fields match a top-level check. Replaying the eight captured trial-64 workflow responses reduced projected content from 262,480 to 115,909 characters (55.84%). This measures response size, not actual paid completion or cost reduction.

Paid trial 43 exposed a recovery gap: after one focus was paused, the model continued investigating independent items without calling `focus`, and the unfocused watchdog terminated the workflow while 21 items remained. Recovery now hands off to an available item as a fallback, retains that item's own progress, advances the native handle and opens a new context epoch. This fallback does not impose an order on ordinary model-selected work; exhaustion with no independent work still stalls. The partial-save `nextCall` also carries the focused decision IDs instead of an empty submission. Offline replay of trial 43 now reaches its final captured turn in `REVIEW_REQUIRED` with `skill:ask-matt` focused, matching the model's next attempted edit. This is control-path evidence, not proof that the real model will save or complete a later run.
