# Wardrobe 通用预设体验重设计

状态：用户已确认整体流程；本机实现与原生 Pi 隔离验收完成，尚未发布。2026-10-19。验证范围与遗留限制见[实施验收记录](wardrobe-preset-redesign-evidence.md)。

## 要解决的问题

Wardrobe 应让不同用户在不同设备上创建、试用、维护和分享自己的 Pi 环境。现有菜单沿用 Perfect Pi 迁移流程，原始配置又享有特殊限制，导致预设不能作为同一种对象管理。只移动菜单条目无法解决创建、编辑与可移植性缺失。

## 决策树

已确认：

- 主入口：`/wardrobe` 首屏为可搜索预设列表，选择即使用。创建、导入和管理另有入口。
  - 原始配置：首次捕获后成为普通预设，具有相同操作。
  - Perfect Pi：没有专用迁移入口，通过通用本地或仓库导入。
- 创作：资源选单和让 Pi 创建/编辑同时支持。
- 可移植性：公共资源默认随预设打包；本机环境依赖使用单独设备绑定。
- 会话：使用预设进入新对话，旧对话保留；不改变启动默认。
  - 默认：全局默认、项目覆盖；清除项目覆盖后跟随全局。
  - 扩展变化：同一终端自动交接，清理旧扩展状态。
- 所有权：模型和认证由 Pi 管理；Pi 与 extension 更新使用原生 `pi update`。
- 维护：跟随预设和上游 skill，保留自定义资源，冲突在安装新版本前解决。

用户已整体确认的细化：

- 列表每个预设只有一行；版本历史进入该预设的管理页。
- 新建可从当前全局环境、已有预设或空白开始。复制生成新身份；编辑上游预设生成本地派生。
- 编辑使用草稿，保存后形成新版本；当前会话继续绑定旧版本，另选“使用”才生效。
- 本地导入接受标准预设目录、`preset.json` 和普通 Pi 配置目录，后者进入同一个资源选择流程。目录不会成为安装后的实时依赖。
- 缺少必需设备绑定时可保存、查看、编辑，但不能使用；可选绑定可以关闭。
- Pi 创作生成待审阅草稿；通过相同的资源检查与变更审阅后保存，不直接改全局配置。
- 导出到本地标准目录；自动发布仓库不在本轮范围内。

## 参考 DeepSeek Harness

核对官方 master 于 2026-10-19：

- [预设选单与 Creator](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/ui-agent-preset/README.md)：统一呈现内置与自定义预设、配置可查看、创作有专门入口，现有会话与新任务默认值分开。
- [预设注册与生命周期](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/preset/agent-preset-registry/README.md)：定义身份、加载状态与已运行实例的生命周期分开；坏定义仍可诊断。

Wardrobe 借鉴这些交互与生命周期原则，继续使用 Pi 资源和标准仓库格式。保留我们已约定的手动资源编辑、历史修订恢复、上游与本地变更合并，不引入 Harness 的 Cordis 配置与专用 Creator 预设。

## 面板

```text
Wardrobe
搜索预设…

❯ 我的原始配置     当前 · 全局默认
  精简写作
  团队开发         可更新

Enter 使用   → 管理   Ctrl+n 创建   Ctrl+o 导入   Esc 关闭
```

搜索直接过滤列表，不再有“搜索”菜单项。当前名称继续显示在 composer 上方。

选中预设的管理选单：编辑、复制、维护、启动默认、导出、更多。更多收纳设备绑定、版本、重命名与移除。无可跟踪上游的本地预设仍可维护：登记来源、维护已登记的 skill、针对当前 Pi 检查兼容性。

创建先选“从当前环境 / 从已有预设 / 从空白创建 / 让 Pi 创建”。编辑页用资源清单呈现 skills、extensions、prompts、themes、偏好及设备需求，保存前显示变更摘要；“让 Pi 编辑”是同一草稿的另一种编辑方式。

导入先选“本地 / GitHub 或 Git / npm”。解析后选择预设、查看资源和设备需求、保存，然后可选择使用。不要展示 plan digest、临时 localhost URL 等安装内部信息。

维护呈现“检查上游预设 / 维护技能 / 查看待审阅变更”。有冲突时保留草稿和冲突清单，不推进维护基线；验证通过后保存新版本，保留旧版及自定义资源。Pi/extension 更新入口不在此页。

## 数据边界

| 对象 | 内容 | 可随预设分享 |
| --- | --- | --- |
| 预设源码 | 身份、说明、资源、偏好、依赖来源与维护基线 | 是 |
| 草稿 | 未审阅的资源/偏好改动，验证与冲突状态 | 只导出已审阅内容 |
| 已保存版本 | 固定源码快照和已解析资源，版本标识 | 公共内容可以 |
| 设备绑定 | 预设声明的需求 → 本机路径、工具或私密配置引用 | 只分享需求声明，不分享本机值 |
| 首次接入备份 | 原生全局配置的恢复材料 | 否 |
| Pi 模型与认证 | 原生模型、提供商、默认模型、凭据 | 否，由 Pi 管理 |

归档备份与用户可编辑的“我的原始配置”分开：备份保持恢复用途；预设通过正常源码、草稿和版本流程维护。不能仅解禁原始配置菜单，继续使用不完整的归档描述。

公共资源复制到自包含预设源码中。Git/npm 来源保留稳定身份和精确版本；本地公共资源保存文件及可用的上游来源。符号链接需判断目标是否可纳入，不能导出指向另一台机器的绝对路径；超出选择范围的目标归为设备需求。私密设置不靠文件名排除就宣称安全，导出检查还需核对资源内容、配置字段及绑定边界。

标准仓库沿用 `package.json`、`preset.json` 和 Pi 资源目录。后续实现先补充设备需求声明与维护元数据契约，并验证单预设和集合仓库的往返导入，不另建 Perfect Pi 专用协议。

## 运行原型与验收路径

内存原型：`.scratch/wardrobe-preset-redesign/prototype.html`。它只模拟菜单、资源和生命周期，不调用模型、不下载资源、不读写本机配置。

必须实际走通：

1. 首次捕获的原始配置与普通预设一样，能创建副本、编辑、维护、导出。
2. 从当前环境创建，取消资源、改名、保存，再显式使用；保存前后原会话不变。
3. 让 Pi 创建/编辑，产物进入待审阅草稿；失败、取消或不通过检查均不改变当前会话。
4. 普通 Pi 目录与标准预设均能通过同一个本地导入入口转换为预设；没有 Perfect Pi 特判。
5. 导出公共资源到另一设备，补齐设备绑定后使用；不带模型、认证或本机绝对路径。
6. 从上游导入后编辑形成派生，维护时同时保留上游改动与自定义 skill；冲突可见且不覆盖旧版。
7. 默认、会话使用、历史版本恢复互不混淆；编辑并保存新版本不改变活跃旧对话。
8. 搜索、返回、取消均保留正确焦点；窄终端、长名称、重名、空列表、离线与失败状态可操作。
9. 沿用真实 Pi RPC/TUI 隔离验收和同资源预热额外启动耗时 ≤500 ms；不在普通启动做维护扫描。

## 已落实

统一源码和草稿、原始配置的普通预设操作、本地/仓库导入、资源与偏好选单、Pi 创作、设备需求及本机绑定、标准目录导出均已接入现有固定快照和审阅保存流程。列表按预设身份分组，旧版放在版本菜单；保存或导入后聚焦到新版本，不自动启用。创建与导入使用 Ctrl 快捷键，以便普通字母直接搜索。

草稿页只列出未保存的用户草稿；导出、添加资源和维护使用的内部快照不占列表。资源关闭后仍保留在目录中，下一版可重新选择；添加扩展同时保留其声明的辅助文件。恢复备份保持独立。
