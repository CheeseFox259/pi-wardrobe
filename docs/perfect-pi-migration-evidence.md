## 开始使用前的条件

按 [中文操作指南](usage.zh-CN.md) 从本地快照安装到独立管理目录，首次离线启动后显式配置 CPA 地址、协议和密钥环境变量。配置模板已由真实 Pi 加载，但没有用户 CPA 端点或密钥，本次没有执行认证后的模型请求、SoL-Pi reducer 或在线压缩。

codebase-memory 0.11.0 的[上游账户协调规则](https://github.com/DeusData/codebase-memory-mcp/blob/v0.11.0/README.md#session-coordination-daemon)要求活动进程使用相同版本、构建和缓存根目录。切换到隔离修订前，正常退出使用旧缓存的全部 CBM 会话；本次没有结束这些现有会话、复用其个人缓存或修改其配置。若需要并行保留旧会话，可先在新修订中禁用该 MCP，再使用其他能力。

浏览器交互、语言服务器、tmux 多任务、MiniMax 和实际项目中的模型驱动流程仍取决于对应主机程序、配置与授权，本次没有对它们逐一执行在线端到端测试。固定顶层版本不表示 npx 的全部传递依赖已由 lockfile 冻结。

代码仍在当前工作区，未提交、推送或发布；也尚未替用户激活一个持久安装。可立即按指南安装并开始使用，以上在线和主机条件需分别满足。

## 2026-10-18 复用原生 Pi 配置并兼容 ccstyle

用户进一步要求直接使用当前原生 Pi 配置、无需再次登录。这一要求替代上文“模型/认证必须在每个修订重新配置”的范围。Perfect Pi 入口将 Pi 1.1.0 的模型运行时、认证存储与模型设置操作委托给启动前的原生目录（默认 `~/.pi/agent`），直接使用原有文件和原生锁。模型默认值、范围及 thinking 等模型设置由 Pi 保存回原生目录；资源、UI 与会话仍在修订目录。普通 Wardrobe 启动不启用该桥，继承环境变量的其他修订也不会启用。模型和认证文件没有复制、符号链接或进入安装锁。

ccstyle 0.9.12 原本在检测到 SoL-Pi 的 write 时主动让出富 diff。新增本地协作入口保留其未修改的 npm 源码，令 ccstyle 的元数据执行器位于 SoL 文件队列内、guarded then_run 之前。只有已识别的合作写入者使用这条链；其他扩展仍显示原来的冲突提示。本地启用扩展现在为 11 个，直接加载的原生扩展减少 1 个，总资源数量不变。
