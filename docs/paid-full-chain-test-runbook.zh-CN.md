# 真实付费全链路测试规程

本规程记录如何用真实 Pi、真实模型和隔离工作区验收 Wardrobe 更新流程。每轮结果只代表该轮记录的源码快照、上游基线、Pi 版本、模型和任务；历史成功或失败不能替代新版本的证据。

只验收人工确认流程时，可以冻结一个范围明确的标准 preset Update 场景。先做原生 RPC 预检，再记录报告全文、确认响应、编辑顺序和独立验收。单一结果用一行说明用户可见变化与保留约束，再用一句说明验收。记录批准状态后结束报告回合，在新 Pi 回合运行原生 Update 开始实施。用实际安装的修订检查请求中的行为及停用状态。用户授权直接同意方案时，驱动器仅对标题完全匹配 `Wardrobe · 更新方案` 的确认返回同意。此场景只执行冻结的 Update 和独立验收，并单独记录范围、费用和各阶段结果。下文的隔离、停机和安装门槛照常适用。

当前执行器与辅助验收脚本位于 `.scratch/wardrobe-update-v2/`。它们是本项目试验工具，不是通用 CLI；新一轮必须复制脚本并更新本节列出的硬编码值。

## 1. 固定测试条件

开始一轮前，先记录并冻结以下输入：

- 唯一轮次 ID 和日期；每轮使用新脚本、新输出目录，禁止覆盖历史证据。
- 本轮 Wardrobe 管理器和预设快照，包括 Git HEAD、是否复制未提交工作树、文件数量与散列。
- 旧版预设、旧 Pi 运行时、目标 Pi 运行时、上游仓库 commit/base/cache，以及 npm 缓存来源。
- 当前原生 Pi 的 provider、model、thinking level。模型选择按这三个字段逐项比较；运行时附带的上下文窗口和价格元数据不参与选择比较。通过原生配置副本和认证运行；凭据文件权限设为 `0600`，报告中不复制凭据。
- 策略场景必须明确区分：原始无 policy 的迁移，或预先含私有 policy 的预设。第 54 轮只在旧预设副本中新增当前仓库的 `skills/preset-policy/SKILL.md`，记录原始清单、散列、唯一新增文件与来源；原旧目录保持不动。不得把此场景当作无 policy 迁移成功。Update 门禁必须从实际 `wardrobe_workflow` 工具结果确认 `origin=preset` 且 body 散列与冻结输入一致；失败阶段也保存策略证据。Maintain 则核对其实际安装起点的策略。
- 本轮冻结的 Import、Update、Maintain 任务、成功条件和阶段顺序。测试运行期间不向模型补充提示、修复候选或提供 Codex 指导。
- 使用 `protocol.json` 记录基线、任务、隔离策略、共享预算、执行器与辅助脚本散列，并写出协议散列。

本执行器的共享上限为 **$50、5,000 个 assistant 回合、6 小时**，由整条链共同消耗，没有单阶段额度。达到任一上限即停止。费用是 Pi 返回的配置价格估算，不等同供应商账单，也不包括 Codex 的观察和报告成本。每阶段均记录模型、token、回合、工具调用、耗时、费用和错误。

## 付款前的已知问题门禁

变更 Update/Maintain 协议后，先完成本次已知问题矩阵、无付费公开工具回归和真实 Pi scripted-provider 链。复合任务的实施覆盖、阻塞与依赖、局部检查失效、取消/额度恢复、上下文投影及最终 inactive 安装都需有对应证据。共享方法、工具 schema 和 preset 组件约定必须一致；组件约定的 companion 文件与入口一起冻结，校验实际来源、路径和内容散列。不能仅复制 SKILL.md 而遗漏其引用的 COMPONENTS.md。

付款前另做隔离历史候选重放与验收器离线检查。记录原候选不变、反事实副本中的具体改动和真实依赖；该重放不算模型成功。独立产品断言在付款前冻结，覆盖模型继承、显式覆盖、取消、fallback、本地功能保留和资源退役。模型可迁移旧默认断言，不能改写独立验收。完整性通过、工作流完成和产品行为通过分别记录。

全部已知问题有解决或明确处置及证据后，才冻结新付费轮次。真实模型的效率收益仍由新一轮完整链测量；无费用脚本不能替代该证据。

## 2. 建立隔离环境

每轮创建全新的隔离 `HOME`、Pi agent 目录、项目副本、安装目录和临时目录。长链的这些目录应位于该轮持久工作根中，使用独立后台 runner，避免宿主重启或临时目录清理迫使重建环境；保存路径映射和累计预算。复制当轮冻结的管理器、预设与运行时；不要让被测流程读开发仓库、其他试验目录或用户原生 Pi agent 目录。仅允许在这轮临时工作区内写文件。

npm 缓存分为输出目录中的不可变种子副本和临时工作区中的运行副本。付款前两者必须与冻结清单一致；运行期间允许 npm 更新运行副本的索引、日志和内容，但须记录增删改清单并核验内容文件与其内容寻址哈希一致。种子副本始终不得改写，不可因运行副本正常变化而重算或放宽种子基线。

上游 Git 缓存同样分为不可变种子和可写运行副本。付款前两者必须与冻结清单一致；运行中允许 fetch 新对象、仓库和元数据，记录全部增删改，并以禁用惰性获取的离线 `git fsck --full --no-reflogs` 校验各仓库对象。拒绝链接和异常文件类型；种子始终校验原散列。

将原生 Pi 的模型和认证文件复制到隔离 agent 目录，设为 `0600`；记录配置散列以便结束后确认原生设置未变。启动时读取并核对实际 model/provider/thinking；不一致则在发送任务前停止。禁止模型选择被脚本或任务覆盖。

所有交互式 UI 请求统一取消，不授予额外权限。任务只使用本轮工作区中的材料和安装版 Pi 文档/API。将 UI 请求、隔离拒绝、RPC 错误及模型工具错误完整记入事件和错误记录。Pi 收到工具错误后可在原生 agent 回路中发起新的纠正调用；纠正调用照常消耗预算。驱动器不重放失败调用、不自动续跑，也不把一次工具失败本身直接算作恢复成功。

## 3. 分阶段执行与门禁

严格按顺序执行。每阶段都必须满足它自己的成功条件；一旦失败、超时、达到预算或进入需要显式恢复的状态，保存现场并停止后续阶段。**候选只有在验证状态为 `READY_TO_INSTALL` 时才允许安装。** 不安装 `CHECK_FAILED`、`STALLED` 或其他未通过验证的候选。

| 阶段 | 操作 | 通过门槛 |
| --- | --- | --- |
| Import | 从旧版预设导入到隔离环境；完成获准的真实 `pi update --self`；读取 Pi 版本 | 导入产生有效 profile；Pi 从记录的旧版本升到本轮目标版本；无 assistant 级错误；原生模型无覆盖；不改启动默认 |
| Update | 对导入的旧预设运行真实 Wardrobe update；检查 Pi 和上游增量、保留本地功能；保存候选；执行验证 | 所需决策和受影响检查完成；资源/技能预检通过；状态明确为 `READY_TO_INSTALL`；然后安装为新修订并保持 inactive。未到此状态即停止 |
| 更新后启动验收 | 对新修订运行原生 Pi RPC 和 TUI 检查 | 必需命令存在；模型 token 为零；状态栏和启动无错误/警告；默认设置不变；启动检查通过后才继续 |
| Maintain | 在实际安装的更新版预设上执行预先写定的单一修复/增强任务，验证并安装新修订 | 候选通过验证并安装；只改本轮候选；不改管理器、安装目录或启动默认；无 assistant 级错误 |
| 独立验收 | 对最终修订运行资源导出审计、工作流分层审计、原生 RPC/TUI 与 reload、重复 update、切换/恢复检查 | 所有独立门禁通过；重复 update 返回 `NO_UPDATE` 且模型 token 为零；TUI 显示正确；切换后新会话可用、旧会话可恢复、默认设置不变 |

独立验收不得把结果反馈给前面的模型任务，也不能据此暗中修改候选。出现失败时应结束本轮，记录结果，再以新轮次验证修复后的版本。

## 4. 新一轮复用步骤

以 `.scratch/wardrobe-update-v2/trial-clean-chain-54.mjs`、`paid-chain-gates-54.mjs` 和同轮次验收脚本为模板。第 52 轮修正模型对象比较与 npm 缓存误判，第 53 轮将 Git 运行缓存与不可变种子分离，第 54 轮增加私有策略输入场景和实际加载门禁；旧执行器和原门禁结论保留为历史证据。开始付款前先运行离线门禁回归：

```sh
node --test .scratch/wardrobe-update-v2/paid-chain-gates-54.test.mjs
```

每一轮：

1. 选择未使用的轮次 ID，复制 driver 和需要随 Pi 版本调整的验收脚本；不要编辑历史脚本或旧证据。
2. 更新 driver 中的 label/output 路径、driver 自身的散列清单、Pi 旧版/目标版、runtime fixture、版本响应 fixture、管理器/预设快照、上游 commit/base/cache 和本轮冻结任务。
3. 检查所有辅助脚本中的硬编码轮次和 Pi 版本，尤其是 同轮次的 `verify-stage-startup`、`verify-native`、`audit-native-exports`、`audit-workflow-layers`、`verify-switch`。让它们使用同一轮次目录和目标 Pi 运行时。启动 Pi 子进程的验收器继续使用该轮沙箱；只读审计器只读本轮候选/工作区，并把输出写入本轮目录。
4. 确认新输出目录不存在。driver 应拒绝复用已存在的结果目录。确认工作区中已有用户改动和旧证据均保留。
5. 先冻结输入，再做不发送任务的原生 RPC 模型/零 token 预检。两步均通过后才运行付费任务，例如（替换为新轮次编号）：

   ```sh
   node .scratch/wardrobe-update-v2/trial-clean-chain-54.mjs --prepare
   node .scratch/wardrobe-update-v2/trial-clean-chain-54.mjs --preflight
   node .scratch/wardrobe-update-v2/quota-probe-54.mjs
   node .scratch/wardrobe-update-v2/trial-clean-chain-54.mjs --run
   ```

   这里的 `54` 只是示例；若已占用，换成新的轮次编号。

6. 若前轮因供应商额度耗尽而停止，冷却时间仅表示代理的重试限制，不保证额度恢复。第 54 轮在预检后须执行一次独立的 `quota-probe-54.mjs`：同模型、无工具、最长 60 秒、费用上限 $0.01，在独立探测配置副本中关闭 agent 与 provider 重试（完整链配置不变），不自动重试，费用单独记录。探测失败则不启动 Import；零 token 预检不能证明供应商额度可用。
7. 观察 driver 的阶段门禁与共享预算；不要在候选未达到 `READY_TO_INSTALL` 时手动续跑或安装。
8. 结束后只读整理本轮证据，形成验收报告。新版本修复若要复验，建立新轮次，不重用旧候选或旧工作目录。

Pi 版本变动时，必须同步更新辅助脚本使用的 CLI 路径；否则检查可能意外针对旧运行时。更改 driver、辅助脚本或输入后，重新冻结并记录散列，再开始付费调用。

## 5. 证据与报告

将证据保存在 `.scratch/wardrobe-update-v2/trials/<轮次标签>/`，至少保留：

- `protocol.json`、`protocol.sha256`、`environment.json`、`budget.json`、`integrity.json`
- 每阶段的 `*-result.json`、`*-model.json`、`*-messages.json`、`*-events.jsonl`、`*-stderr.txt`
- 工作流产生的候选、差异、验证结果、诊断、阶段 gate 与 profile/revision ID
- `independent-gates.json`、各验收器输出、最终 `acceptance-result.json` 和人工编写的 `assessment.md`

报告按四类列出结果：

- **Verified**：本轮有直接证据通过的行为；注明命令/路径及证据文件。
- **Blocked**：遇到的失败门禁、错误或停止点；写清状态、诊断尾部和被保留的候选。
- **Not run**：因前置门禁失败而未执行的检查；不可记为通过。
- **Not applicable**：前置条件不存在，因此明确不适用的动作，例如候选未达安装门槛时的激活检查。

另附阶段耗时、assistant 回合、工具调用、token、估算费用、累计用量、实际模型、UI 请求数和是否存在工具错误。不要把模型生成的候选、未验证的改动或历史试验结果写成通过证据。带本机路径、模型配置和消息内容的原始记录保留在本机试验目录，不直接发布。

## 6. 第 48 轮示例：如何记录门禁失败

第 48 轮 Import 通过：旧预设导入完成，Pi 从 `1.0.4` 升至 `1.3.0`。Update 候选验证返回 `CHECK_FAILED`，诊断包含 `resource path refused`，工作流随后停在 `STALLED`，要求显式恢复。候选没有达到 `READY_TO_INSTALL`，所以没有安装，Maintain 和后置验收均未运行。

本轮累计 `$0.47625354`、212 个 assistant 回合、269 次工具调用，历时 27 分 24 秒；管理器、内置预设和原生 Pi 配置完整性检查通过。报告为 **Blocked at update gate**，后续步骤列为 **Not run**，安装与激活列为 **Not applicable**。详细记录见 `.scratch/wardrobe-update-v2/trials/48-paid-full-chain-2026-10-28/assessment.md`。
