# Perfect Pi design policy

Perfect Pi supports full-stack engineering with Matt Pocock workflows adapted to native Pi. Keep upstream methodology and local interaction improvements together. Use the shared Wardrobe method for execution.

- Preserve the local enhancements declared in `components.json`, including grilling’s interactive questionnaire, amend key, recommended answers, and non-interactive fallback.
- Keep routing advisory: `/skill:route` recommends a workflow and leaves execution to the user. Carry prior answers and authorization through subsequent steps.
- Let native Pi own models, authentication, subagents, and compaction. Integrations use public Pi interfaces and preserve the user’s model/provider choices.
- Keep workflows focused: update integrates upstream changes; maintain repairs a requested behavior or adds a requested capability. Select checks that demonstrate affected behavior and preserve evidence for completion claims.
- Preserve local skills and unrelated user resources. Record upstream lineage so subsequent updates can distinguish upstream changes from local adaptations.
- Adopt useful compatible upstream capabilities when they support these principles. When an optional capability has ambiguous behavioral tradeoffs, preserve existing habits and explain the deferral. Ask when an explicit user requirement depends on the unresolved choice.

Use these defaults for affected features. For question UI, routing/workflow entries, skills/lineage, native model/compaction, SoL-Pi, presentation, or MCP changes, read the corresponding [component maintenance contract](COMPONENTS.md). It defines defaults, user overrides, preservation boundaries and observable outcomes. Paths are relative to the preset root. The listed checks are starting points for affected behavior.

Defer optional broad discovery or automatic adoption. | `scripts/managed-mcp.mjs`, `scripts/mcp-config.mjs`; use affected cases in `managed-mcp.test.mjs` and, for startup/selection changes, `mcp-smoke.test.mjs`. |

Legacy setup/doctor tests exercise the previous installer, not Wardrobe's native acceptance. Select them when changing that installer or its contracts. In particular, `habits.test.mjs` invokes setup and writes the current agent settings; use the shared method's isolated check environment.

For changes outside these rows, apply the principles above to the affected component and its `components.json` preservation declarations. Consult the preset README when workflow purpose or managed MCP ownership remains unresolved. Explicit user requirements take precedence over these defaults; use the shared method for unresolved choices, evidence, verification, and installation.
